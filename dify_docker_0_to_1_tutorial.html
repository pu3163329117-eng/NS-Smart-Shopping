Docker Self-Host Guide

Dify 从 0 到 1 部署教程

同一套教程覆盖 Windows + WSL2 和 macOS，用 Docker Compose 在本地跑起完整 Dify。

目标时长：30~50 分钟 阅读方式：从上到下照做 结果：可登录、可建应用、可测试模型
准备（Windows） 准备（macOS） 开工前检查 拉源码 启动容器 容器检查 初始化 验证 运维 排障

你会得到什么

1. 一键启动

完成 Dify 源码下载、`.env` 初始化、容器启动和状态检查。

Step 00

安装 Docker（Windows + WSL2）

先确认 Windows 版本（本教程适用范围）

建议使用 `Windows 10 专业版/企业版/教育版 22H2` 或 `Windows 11 22H2+`。如果是家庭版，请先确认当前 Docker Desktop 的支持范围和功能限制。

winver systeminfo | findstr /B /C:"OS Name" /C:"OS Version" wsl --version

A. 先做系统检查（PowerShell 管理员）

winver systeminfo | findstr /i "Virtualization" wsl --status

确保 BIOS 已开启虚拟化；若 `wsl` 不可用，继续执行下一步安装。

B. 安装和启用 WSL2（PowerShell 管理员）

wsl --install wsl --update wsl --set-default-version 2 wsl -l -v

重启系统后，确认你安装的发行版版本是 `2`。

C. 安装 Docker Desktop

从 Docker 官网下载安装包，安装时保持 WSL2 相关选项开启。首次启动等待状态变成 Running。

如果遇到权限问题，可将当前用户加入 `docker-users` 组后重新登录系统。

net localgroup docker-users "%USERNAME%" /add

D. 验证 Docker 可用（在 WSL2 终端）

docker --version docker compose version docker run --rm hello-world

`hello-world` 运行成功，再进入 Dify 部署步骤。

Step 01

安装 Docker（macOS）

A. 系统检查（终端）

sw_vers uname -m

确认系统版本在 Docker Desktop 支持范围内，并识别机器是 Apple Silicon 还是 Intel。

B. 安装 Docker Desktop

推荐官网下载安装。若你使用 Homebrew，也可安装 cask 后手动打开应用完成初始化。

brew install --cask docker open -a Docker

C. 可选：Apple Silicon 装 Rosetta

softwareupdate --install-rosetta --agree-to-license

部分旧镜像可能需要 Rosetta，装好后兼容性更稳。

D. 验证 Docker 可用

docker --version docker compose version docker run --rm hello-world

确保输出正常后，再继续 Dify 启动。

Step 02

部署前准备

项目 最低建议 说明
CPU / 内存 2 Core / 4 GiB macOS 建议把 Docker Desktop 提升到 8 GiB 内存，稳定性更好。
Docker Docker Desktop 最新稳定版 Windows 需要开启 WSL2；macOS 直接安装 Desktop。
Windows 版本 Win10 专业/企业/教育 22H2 或 Win11 22H2+ 本教程按上述版本编写，先执行 `winver` 再继续。
Git 任意近两年版本 用于拉取 Dify 源码。
网络 可拉取 Docker 镜像 首次启动会下载多个镜像，可能需要较长时间。
端口可用性 80 端口可用 默认通过 `http://localhost` 访问，如有冲突需调整端口映射。
模型 API Key 至少 1 个可用 建议提前准备，部署完成后马上做模型连通性验证。

端口检查（Windows PowerShell）

netstat -ano | findstr :80

端口检查（macOS / WSL2）

lsof -i :80

Windows 关键提醒

请把项目放在 WSL2 的 Linux 文件系统路径里（例如 `~/projects`），不要放 `C:` 盘再跨挂载跑容器。

macOS 关键提醒

Docker Desktop 里把内存调到 8 GiB（或更高）后再启动，避免构建或运行中途失败。

Step 03

系统自检（双系统）

先验证 Docker 和 Compose 可用，后续报错会少很多。

Windows（在 WSL2 终端执行）

docker --version docker compose version uname -a

macOS（终端执行）

docker --version docker compose version sw_vers
如果 `docker` 找不到，先打开 Docker Desktop 并等待状态变成 Running 再继续。
Step 04

获取 Dify 源码并进入 Docker 目录

官方推荐优先使用最新 release 标签；如果你先求稳，也可以直接 `git clone` 主仓库再手动切版本。

Windows（WSL2）

# 建议先进入 Linux 家目录 cd ~ # 拉取仓库（简洁方案） git clone https://github.com/langgenius/dify.git cd dify/docker

macOS

cd ~ git clone https://github.com/langgenius/dify.git cd dify/docker
如果你有版本锁定要求，建议在 `dify` 根目录执行 `git fetch --tags` 后 `git checkout <tag>`。
Step 05

初始化环境文件并启动容器

Windows（WSL2）

cp .env.example .env docker compose up -d

macOS

cp .env.example .env docker compose up -d
正常情况下会拉起核心服务：`api`、`worker`、`worker_beat`、`web`、`plugin_daemon`，以及依赖组件：`db_postgres`、`redis`、`weaviate`、`nginx`、`ssrf_proxy`、`sandbox`。
Step 06

检查容器状态

docker compose ps

重点看状态列：大多数服务应为 `Up`，数据库通常会显示 `healthy`。

通过
服务大多 `Up/healthy`，可以继续初始化。
可等待
单个服务处于 `health: starting`，再等 30~90 秒重试。
需排障
`Exited` 或反复重启，先看日志再处理。
Step 07

首次初始化与登录

1. 初始化管理员

http://localhost/install

设置管理员邮箱和密码，完成初始化向导。

2. 进入控制台

http://localhost

使用刚创建的管理员账号登录。

如果你部署在远程服务器，把 `localhost` 替换为服务器 IP 或域名，例如 `http://your_server_ip/install`。
Step 08

最小可用验证（5 分钟）

验证 A：配置模型提供商

控制台中进入模型供应商设置，填入你的 API Key，保存后做一次连接测试。

验证 B：创建一个聊天应用

新建应用后发送一句测试问题，能返回有效答案说明主链路已经通。

这一步成功后，后续知识库、工作流、插件都是增量能力，不影响基础部署是否完成。
Step 09

常用运维命令

动作 命令
查看服务状态 docker compose ps
查看全部日志 docker compose logs -f
查看 API 日志 docker compose logs -f api
停止服务 docker compose down
后台重启 docker compose down && docker compose up -d
拉取镜像后更新 docker compose pull && docker compose up -d
Step 10

高频报错排查

报错：端口 80 被占用

先停掉本机占用 80 端口的服务，或者修改 Docker 配置映射到其他端口后再访问。

报错：容器频繁重启 / OOM

优先增加 Docker Desktop 内存，尤其是 macOS；然后执行 `docker compose logs -f` 找首个报错服务。

报错：Windows 路径性能差或权限异常

确认仓库在 WSL2 Linux 文件系统目录中运行，不要在 `C:\` 盘路径直接绑定。

报错：登录状态异常（跨子域）

前后端不同子域时，在 `.env` 里按文档设置 `COOKIE_DOMAIN` 和 `NEXT_PUBLIC_COOKIE_DOMAIN=1`。
