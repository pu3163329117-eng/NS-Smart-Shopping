# 谷市项目交接说明 (Handover for Antigravity)

- 日期：2026-03-18
- 项目：Smart JA Web / 谷子二次元 / 谷市
- 当前状态：PRD 与交付拆分已完成，尚未开始代码落地

## 1. 这次要做什么

谷市不是一个金融产品，而是一个面向二次元谷子与周边的：

- 实时行情系统
- 标准单品交易市场
- 托管式寄售交易模块

第一阶段目标很明确：

1. 用户能看行情
2. 卖家能挂单
3. 买家能下单
4. 平台能托管结算
5. 成交能反哺行情

## 2. 为什么不能直接复用现有市场链路

当前项目里已经有：

- `src/views/Market.vue`
- `server/routes/market.js`
- `server/routes/orders.js`
- `server/prisma/schema.prisma`

但这些链路不够承接谷市，原因如下：

### 2.1 `Service` 不适合做谷市标准单品

现有 `Service` 偏创作者商品/服务模型，不是“同款谷子聚合模型”。

### 2.2 `/api/orders` 是即时结算

现有 `server/routes/orders.js` 会在买家下单时：

- 直接扣买家余额
- 直接给卖家记收入

谷市必须改成：

- 买家先支付到托管
- 卖家发货
- 买家确认收货
- 再释放给卖家

### 2.3 谷市需要独立的价格聚合逻辑

谷市的“最新价 / 参考价 / 地板价 / 涨跌幅”都依赖标准单品 + 完成订单聚合，这不是普通商品列表能自然承担的职责。

## 6. 必须遵守的边界

1. 不要把谷市标准单品直接塞进 `Service`
2. 不要让谷市订单走现有 `/api/orders` 的即时结算
3. 不要把谷市所有逻辑堆进现有 `MarketService`
4. 不要在前端用 `isAdmin` 路由 meta 充当后端权限校验

## 7. MVP 的最小 Definition of Done

只有以下能力全部具备，谷市 MVP 才算真正成立：

1. 平台有标准单品池
2. 卖家能在标准单品下发布挂单
3. 买家能查看行情和当前在售单
4. 买家能完成托管下单
5. 卖家能发货并填写物流
6. 买家能确认收货
7. 卖家在确认收货后才收到款项
8. 已完成订单会更新单品行情

## 8. 当前主要风险

### 风险 1

误复用现有普通订单链路，导致结算时机错误。

### 风险 2

缺少标准单品池，导致同款无法聚合，价格没有可信度。

### 风险 3

低样本阶段行情容易失真，需要在前端明确样本量。

## 9. 一句话结论

谷市最正确的落地方式不是“给现有市场页再加一点字段”，而是：

- 复用现有用户、钱包、上传、鉴权基础设施
- 独立建设标准单品、挂单、托管订单、行情快照四条主线

如果按这个边界推进，谷市可以在不打乱现有 Smart JA Web 主体结构的前提下，成为一个清晰、可扩展的新业务模块。
